# دليل تشغيل ونشر حزمة VIARA RCMS على خادم العميل

> **إشعار أرشفة:** هذا دليل قديم غير معتمد، وتعليماته وبيانات الدخول الواردة فيه غير صالحة للإصدار الحالي. لا تستخدم `.env` أو أي بيانات اعتماد أو ترخيص تجريبي مذكور أدناه. استخدم [دليل تشغيل العميل الحالي](../../docs/CLIENT_DEPLOYMENT_OPERATIONS_AR.md)، ولا تنشر إلا حزمة وصور إصدار معتمدة من VIARA.

## 1. المتطلبات الفنية الدنيا للخادم (System Requirements)

| المكون | الحد الأدنى للتشغيل التجريبي | الموصى به للإنتاج (Production) |
| :--- | :--- | :--- |
| **نظام التشغيل** | Ubuntu 22.04 LTS / Debian 12 / Windows Server 2022 | Ubuntu 24.04 LTS / RHEL 9 |
| **المعالج (CPU)** | 4 Cores | 8 Cores (Xeon / AMD EPYC) |
| **الذاكرة (RAM)** | 8 GB | 16 - 32 GB |
| **سعة التخزين** | 50 GB SSD | 500 GB+ NVMe SSD (وفق حجم فحوصات الـ DICOM) |
| **البرمجيات** | Docker v24+ مع Docker Compose v2.24+ | Docker Engine الحديث + Nginx Reverse Proxy |

## 2. خطوات التثبيت والتشغيل (Quick Installation)

### الخطوة 1: فك ضغط الحزمة ونقلها للخادم
قم بنقل مجلد الحزمة `viara-production-package` إلى الخادم في المسار المفضل (مثلاً `/opt/viara`):
```bash
sudo mv viara-production-package /opt/viara
cd /opt/viara
```

### الخطوة 2: فحص متغيرات البيئة ومفتاح الترخيص
هذا الدليل مؤرشف؛ لا يوجد ملف إعداد صالح للنشر ضمن هذا المجلد. استلم حزمة الإصدار ومراجع الصور المثبتة والإعدادات السرية والترخيص من VIARA عبر قناة آمنة.
```bash
# التأكد من صلاحيات الملف الأمنية (على لينكس)
chmod 600 .env
chmod +x scripts/*.sh
```
*ملاحظة:* إذا كان الخادم سيعمل بنطاق إنترنت مخصص (مثلاً `viara.center.com`)، قم بفتح `.env` وتعديل:
```env
CLIENT_URL=https://viara.center.com
ALLOWED_ORIGINS=https://viara.center.com
```

### الخطوة 3: تشغيل النظام
* **على خوادم Linux / macOS:**
  ```bash
  ./scripts/start.sh
  ```
* **على خوادم Windows Server:**
  انقر نقراً مزدوجاً على:
  ```cmd
  scripts\start.bat
  ```

## 3. خيارات البيانات التجريبية (Demo Data) — التضمين أو الاستغناء

يتيح النظام مرونة كاملة في التعامل مع البيانات التجريبية السريرية:

### أ. أثناء معالج الإعداد الأولي (Onboarding Wizard)
عند تسجيل الدخول لأول مرة، يعرض معالج الإعداد خياراً تفاعلياً واضحاً:
* **تضمين بيانات تجريبية استكشافية (موصى به للتقييم):** يقوم تلقائياً بإنشاء غرف فحص، أجهزة أشعة، فحوصات، و5 مرضى ومواعيد لاختبار دورة العمل فوراً.
* **الاستغناء عن البيانات التجريبية (بدء نظيف):** يبدأ بقاعدة بيانات فارغة وخالية تماماً لإدخال بيانات المركز الفعلية مباشرة.

### ب. عبر واجهة إعدادات النظام (Admin Settings)
يمكن لمدير النظام في أي وقت من قسم **إعدادات النظام ← الحوكمة والصيانة** (`/settings?tab=admin&subtab=governance`):
* الضغط على **"🌱 تحميل البيانات التجريبية"** لحقن بيانات استكشافية.
* الضغط على **"🗑️ إزالة البيانات التجريبية"** لحذف السجلات التجريبية بأمان واستعادة قاعدة بيانات نظيفة.

### ج. عبر سطر الأوامر (Scripts)
* **على لينكس:** `./scripts/seed-demo.sh`
* **على ويندوز:** `scripts\seed-demo.bat`

## 4. بيانات دخول المسؤول الأولي

تُسلّم بيانات المسؤول عبر إجراء onboarding آمن خاص بالإصدار. لا تستخدم بيانات اعتماد افتراضية أو ملفات إعداد محلية من مساحة التطوير.

## 5. إدارة وفحص الترخيص وبصمة العتاد

1. **التحقق من حالة وسريان الترخيص:**
   ادخل من الواجهة إلى: **إعدادات النظام ← الترخيص والإصدار** (`/settings?tab=admin&subtab=license`).
   ستجد:
   * اسم العميل المثبت في الترخيص الصادر لهذا الإصدار.
   * عداد الأيام المتبقية التنازلي مع تاريخ الانتهاء.
   * إحصائيات استهلاك الحصص (المرضى، المواعيد، المستخدمين، والتقارير اليومية).
   * **بصمة عتاد الخادم (Hardware Fingerprint):** يمكنك نسخها بنقرة زر عند الرغبة في طلب رخصة إنتاجية مقفلة بعتاد هذا الخادم.

2. **ترقية الترخيص بدون إيقاف الخدمة (Hot Upgrade):**
   عند شراء المركز للنسخة الدائمة:
   * **عبر الواجهة:** من نفس شاشة الترخيص، ارفع ملف الترخيص الجديد `.txt` واضغط **"تفعيل المفتاح الآن"**.
   * **أو عبر سطر الأوامر:**
     ```bash
     ./scripts/update-license.sh "<NEW_LICENSE_KEY>"
     ```
   سيتم التفعيل فورياً دون فقدان أي بيانات مسجلة أثناء فترة التجربة.

## 6. الصيانة والنسخ الاحتياطي

* **أخذ نسخة احتياطية فورية لقاعدة البيانات:**
  ```bash
  ./scripts/backup.sh
  ```
  تُحفظ النسخ الناتجة مضغوطة في مجلد `backups/`.
* **إيقاف النظام:**
  ```bash
  ./scripts/stop.sh
  ```
