01

جهّز بيئة التشغيل

استخرج الحزمة وافتح الطرفية داخل مجلدها، حيث يوجد ملف setup.sh.

نفّذ الأوامر على خادم Linux مخصص، باستخدام حساب لديه صلاحية تشغيل Docker.

Docker Engine + Compose

محرك Linux يعمل، مع Docker Compose v2.

Python 3 + OpenSSL + Bash

أدوات الإعداد وتوليد المفاتيح. لا يلزم تثبيت Node.js لدى العميل.

نطاقان وترخيص الموقع

رابط HTTPS للموظفين، وآخر للبوابة، وترخيص صالح من المورّد.

التخزين والنسخ الاحتياطي

جهّز السعة بحسب حجم الصور وفترة الاحتفاظ، وخطة استعادة قابلة للاختبار.

افحص أدوات التشغيل
docker compose version && python3 --version && openssl version && docker info --format '{{.OSType}}'

يجب أن تظهر الإصدارات ثم كلمة linux. إذا توقف الأمر، جهّز الأداة المطلوبة قبل المتابعة.

02

شغّل معالج الإعداد

أمر واحد لإعداد الموقع وتشغيل الخدمات وإنشاء المدير الأول.

bash setup.sh
  • 1
    أدخل رابطَي الموقع

    رابط الموظفين ورابط بوابة المريض بصيغة HTTPS وعلى نطاقين منفصلين. مثال: clinical.example.com وportal.example.com.

  • 2
    أدخل الترخيص وإعداد اتصال الأجهزة

    استخدم الترخيص الذي استلمته بشكل منفصل. يبقى استقبال DICOM على الجهاز نفسه افتراضياً؛ يحدد مسؤول الشبكات عنوان الاستقبال الداخلي المناسب.

  • 3
    انتظر بدء الخدمات

    يفحص المعالج جاهزية الخدمات. قد يستغرق تحميل صور الحزمة وبدء فحص الفيروسات عدة دقائق؛ اقرأ رسالة الخطأ إذا توقف.

  • 4
    أنشئ حساب مدير الموقع

    عند خلو قاعدة البيانات، أدخل الاسم والبريد وكلمة مرور خاصة من 16 حرفاً على الأقل. يُطلب تغييرها عند أول دخول.

للتشغيل اللاحق: استخدم الأمر نفسه. تُحفظ المفاتيح والحسابات الموجودة. لا يُعاد فتح أسئلة إعداد الموقع بعد نجاح الإعداد الأول؛ تعديلها موضح في الدليل التفصيلي.

تُدخل الأسرار في الطرفية، ولا يحتاج هذا الدليل إلى بيانات الحساب أو الترخيص.

03

تحقق قبل التسليم

ابدأ بحالة الخدمات، ثم أكمل التحقق من الموقع وسير العمل.

docker compose ps

الخدمات المستمرة تكون running وhealthy حيث يوجد فحص صحة. مهمة migrate تنتهي بنجاح ولا تبقى قيد التشغيل.

ضع علامة بعد التحقق الفعلي. هذه قائمة يدوية؛ لا يفحص المتصفحُ الخادمَ، ولا تُحفظ اختياراتك بعد إعادة تحميل الصفحة.

0 من 5 نقاط مكتملة — ابدأ بالتحقق من حالة الخدمات.

نجاح المعالج يؤكد التشغيل التقني. اعتماد الاستخدام الطبي يتطلب إكمال اختبارات الموقع وسير العمل بواسطة الفريق المسؤول.
04

مساعدة واضحة عند الحاجة

نفّذ أوامر التشخيص من مجلد الحزمة نفسه.

تحقق من اكتمال إعداد Compose دون طباعة القيم السرية.

docker compose config --quiet

النجاح لا يطبع مخرجات. رسالة الخطأ تحدد الإعداد الناقص.

اعرض آخر رسائل الخادم عند فشل التشغيل أو الدخول.

docker compose logs --tail 80 backend

راجع السجل محلياً ونقّح الأسرار وبيانات المرضى قبل مشاركة أي مقتطف مع الدعم.

توقف الإعداد، ماذا أفعل؟

راجع رسالة الطرفية، وتحقق من اتصال Docker وصحة الترخيص واكتمال روابط الموقع. بعد معالجة السبب، أعد أمر تشغيل المعالج. إذا لم ينجح الإعداد الأول، يُتاح إدخال إعدادات الموقع مجدداً.

الخدمات تعمل، لكن رابط الموقع لا يفتح

منفذ الخدمة المحلي يختلف عن رابط HTTPS. يتحقق مسؤول الشبكات من DNS والشهادة ومدخل HTTPS وتوجيه كل نطاق إلى خدمته. معالج الإعداد لا يصدر الشهادات ولا يجهز الشبكة الخارجية.

كيف أتيح الوصول من خارج المركز؟

تُربط البوابة العامة بمدخل HTTPS مخصص. يتاح RIS وPACS وقائمة العمل للموظفين عبر الشبكة الداخلية أو VPN/ZTNA المعتمد. راجع قوالب remote-access مع مسؤول الموقع؛ لا تنشر منافذ قاعدة البيانات أو DICOM مباشرة على الإنترنت.

أين أجد تعليمات التحديث وإعداد الموقع؟

افتح دليل التثبيت والتشخيص لتفاصيل إعداد الموقع والتحديث وحماية المفاتيح. احتفظ بملف .env ووحدات البيانات والنسخ الاحتياطية عند التحديث.
