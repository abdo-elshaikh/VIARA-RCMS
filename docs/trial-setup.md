# VIARA RCMS — دليل إعداد وتشغيل النسخة التجريبية (Trial Edition Setup Guide)

> **الإصدار**: 2.0  
> **تاريخ التحديث**: سبتمبر 2026  
> **الجمهور المستهدف**: فريق المبيعات، مهندسو النشر (DevOps)، ومديرو النظام.

---

## 🌟 1. نظرة عامة (Overview)

النسخة التجريبية (**VIARA Trial Edition**) صُممت لتمكين العميل المحتمل (مراكز الأشعة والعيادات التخصصية) من تجربة النظام واستكشاف مميزاته سريرياً وتشغيلياً قبل توقيع عقد الشراء والاشتراك، مع الحفاظ على **الحماية القصوى لملكية النظام ومنع استخدامه كنظام إنتاجي دائم بدون ترخيص**.

### الخصائص الرئيسية للنسخة التجريبية:
| الخاصية | القيمة الافتراضية | طريقة الضبط |
|---------|-------------------|-------------|
| **مدة التجربة** | 14 - 30 يوماً | حقل `expiresAt` في المفتاح المشفر |
| **الحد الأقصى للمرضى** | 50 مريضاً | `quotaService.js` |
| **الحد الأقصى للمواعيد** | 100 موعد / شهر | `quotaService.js` |
| **المستخدمون النشطون** | 3 مستخدمين كحد أقصى | `license.maxUsers` |
| **التقارير اليومية** | 10 تقارير / يوم | `quotaService.js` |
| **العلامة المائية** | "نسخة تجريبية - VIARA TRIAL" | تظهر تلقائياً على كافة الفواتير والوصولات والتقارير المطبوعة |
| **الميزات المقيدة** | PACS، المالية الشاملة، الموارد البشرية، التأمين، تصدير النسخ الاحتياطية | `checkFeature` middleware & `FeatureLocked.jsx` |
| **معدل الطلبات** | 200 طلب / 15 دقيقة للنقاط الحساسة | `trialAwareLimiter` |

## 🔑 2. توليد مفتاح الترخيص التجريبي (Generating Trial License)

يتم توليد المفاتيح حصرياً لدى جهة التطوير عبر أداة التوقيع الرقمي `generate-license.js` باستخدام خوارزمية **ECDSA P-256**.

### الخطوة 1: التأكد من وجود مفتاح التوقيع الخاص (Private Key)
يجب أن يتواجد المفتاح في مسار `keys/privateKey.pem` (محمي وغير متاح للعميل نهائياً):
```bash
node scripts/generate-keypair.js
```

### الخطوة 2: إصدار مفتاح تجريبي للعميل

**الطريقة التفاعلية (موصى بها):** تشغيل السكربت بدون وسائط يطلب كل حقل خطوة بخطوة، ويعرض ملخصاً قبل التوقيع:
```bash
node scripts/generate-license.js
```

**الطريقة غير التفاعلية:** لتوليد مفاتيح بشكل آلي أو متكرر:
```bash
node scripts/generate-license.js \
  --customer "AL-NOOR-RADIOLOGY" \
  --edition trial \
  --days 30 \
  --max-users 3
```

الخيارات الكاملة عبر `node scripts/generate-license.js --help`، ومنها `--verify <key>` للتحقق من مفتاح لاحقاً، و`--env <file>` لكتابة المفتاح مباشرة في ملف `.env` للعميل.

**المخرجات الناتجة:**
```text
✅ VIARA License Key Generated

  Customer     AL-NOOR-RADIOLOGY
  Edition      trial (Trial)
  Issued       2026-09-29T00:00:00.000Z
  Expires      2026-10-29 (30 days left)
  Max users    3
  Fingerprint  None (binds on first activation)
  Modules      9 module(s): appointments, patients, reception, display, chat, notifications, profile, hr, finance

--- LICENSE KEY (set as LICENSE_KEY in .env) ---
eyJ2IjoxLCJjdXN0b21lcklkIjoiQUwtTk9PUi1SQURJT0xPR1kiLC...
------------------------------------------------
```

## 🚀 3. تثبيت وتشغيل النسخة التجريبية لدى العميل

### الخطوة 1: ضبط متغيرات البيئة (`.env`)
في مجلد المشروع على خادم العميل، أضف المفتاح والمتغيرات المرتبطة:
```env
# الترخيص الرقمي المشفر
LICENSE_KEY="eyJ2IjoxLCJjdXN0b21lcklkIjoiQUwtTk9PUi1SQURJT0xPR1kiLC..."

# روابط الترقية والتواصل مع المبيعات
UPGRADE_URL="https://viara.net/pricing"
SALES_CONTACT_URL="https://viara.net/contact-sales"
```

### الخطوة 2: تشغيل الخادم
```bash
npm start
```
عند بدء التشغيل، يقوم `server.js` بالتحقق الفوري من التوقيع الرقمي وتاريخ الصلاحية:
```text
[info]: ✅ License verified — edition: trial, customer: AL-NOOR-RADIOLOGY, expires: 2026-10-29T00:00:00.000Z
```

## 🖥️ 4. تجربة العميل الأولى (Onboarding Flow)

1. **معالج الإعداد الأولي (`/onboarding`)**:
   - عند أول تسجيل دخول لمدير المركز، يتم تحويله تلقائياً لمعالج خطوة-بخطوة.
   - الخطوة 1: الترحيب والتعريف بالنظام.
   - الخطوة 2: إدخال اسم المركز وشعاره وبيانات الاتصال.
   - الخطوة 3: إضافة أول طبيب أشعة وغرفة فحص.
   - الخطوة 4: حجز أول موعد تجريبي.
   - الخطوة 5: شاشة النجاح مع روابط سريعة للبدء وزر حجز عرض توضيحي مع فريق المبيعات.

2. **الشريط العلوي التنبيهي (`TrialBanner.jsx`)**:
   - يظهر بشكل دائم في أعلى لوحة التحكم لعرض عدد الأيام المتبقية.
   - يتحول إلى اللون الأصفر التحذيري عند بقاء أقل من 7 أيام.
   - يتحول إلى اللون الأحمر عند بقاء أقل من 3 أيام مع زر "طلب الترقية الآن".

3. **شاشة الميزات المقيدة (`FeatureLocked.jsx`)**:
   - عند محاولة الوصول لأي قسم محجوب (مثل نظام الفواتير المتقدم أو أرشفة الـ PACS)، تظهر بطاقة أنيقة توضح أن الميزة تتطلب الترقية للإصدار Standard أو Enterprise مع زر مباشر للتواصل.

4. **العلامات المائية على المطبوعات**:
   - تظهر علامة "نسخة تجريبية" مائلة شبه شفافة في خلفية كافة فواتير المرضى وإيصالات القبض والتقارير الطبية.

## 🔄 5. ترقية العميل إلى النسخة الكاملة بعد التعاقد (Upgrade Process)

عند إتمام التعاقد مع العميل، **لا يتطلب الأمر إعادة تثبيت النظام أو فقدان أي بيانات مدخلة أثناء التجربة**:

1. يقوم مسؤول المبيعات بإصدار مفتاح دائم أو سنوي (أو عبر المعالج التفاعلي بدون وسائط):
   ```bash
   node scripts/generate-license.js \
     --customer "AL-NOOR-RADIOLOGY" \
     --edition standard \
     --days 365 \
     --max-users 15
   ```
2. استبدال قيمة `LICENSE_KEY` في ملف `.env` الخاص بالعميل بالمفتاح الجديد.
3. إعادة تشغيل الخدمة (`pm2 restart viara-backend` أو `docker-compose restart`).
4. يتم فتح كافة الميزات المقيدة تلقائياً، وتختفي العلامات المائية وأشرطة التنبيه فوراً، مع الحفاظ على كل المرضى والفحوصات والبيانات المسجلة مسبقاً.

## 🛡️ 6. آليات الأمان ومنع التحايل (Security & Anti-Tampering)

- **التوقيع التشفيري ECDSA P-256**: أي تعديل لحرف واحد في نص المفتاح يؤدي إلى فشل التحقق وتوقف الخادم فوراً.
- **ربط البصمة Hardware Binding**: يتم ربط الترخيص بمواصفات الخادم الفيزيائية عند أول تشغيل لمنع نسخ النظام على خوادم أخرى.
- **الفحص الدوري Ping Job**: يقوم بمراقبة سلامة الترخيص وإرسال إحصائيات النشاط وحالات تجاوز الحصص تلقائياً.
