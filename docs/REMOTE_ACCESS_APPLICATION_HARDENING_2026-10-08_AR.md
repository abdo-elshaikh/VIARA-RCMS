# تقوية أمان التطبيق للوصول عن بُعد — المرحلة الثانية

التاريخ: 2026-10-08. النطاق: جلسات بوابة المرضى والأطباء المحولين، تنزيل المستندات والفواتير، وضوابط حزمة النشر المحلية. يكمل هذا التقرير [التصميم المعماري](RIS_ON_PREMISE_REMOTE_ACCESS_ARCHITECTURE_2026-10-08_AR.md) و[تنفيذ المرحلة الأولى](REMOTE_ACCESS_HARDENING_IMPLEMENTATION_2026-10-08_AR.md).

## الملخص التنفيذي

أُصلحت مشكلة كانت تمنع المتصفح من إرسال ملف تجديد جلسة البوابة إلى مساره الصحيح. أصبح الخروج يلغي عائلة رموز التجديد والجلسة المرتبطة بها حتى دون رمز وصول صالح، مع الحفاظ على أي دخول أحدث للحساب. وأصبح تنزيل المستندات يمر عبر الخادم للتحقق من ملكيتها وظهورها للمريض وسلامة موقع تخزينها. أضيف مسار خاص بالمريض لتنزيل فاتورة PDF فعلية بدلاً من استخدام مسار موظفين يعيد HTML.

نجحت الاختبارات المذكورة أدناه، ومنها تكامل فعلي مع PostgreSQL معزولة وطلبات HTTP. هذه النتيجة تثبت سلوك المسارات المختبرة، ولا تمثل اعتماداً نهائياً لتشغيل RIS/PACS كاملاً في الإنتاج. لم تُعدّل قاعدة بيانات العميل أو مفاتيحه الحالية، ولم تُنشر الخدمات.

## النتائج والإصلاحات

|---|---|---|

| اختلاف ترتيب أقفال عمليات الجلسات | مرتفع عند التزامن: خطر تعارض التجديد والخروج | معاملة PostgreSQL تقفل الحساب أولاً ثم تعدّل الرموز، مثل الدخول والتجديد، مع التراجع عند الفشل وتحرير الاتصال |

| صور حاويات احتياطية تعتمد على tags متغيرة | مرتفع: إصدار غير قابل لإعادة الإنتاج | جعل متغيرات الصور مطلوبة وحذف قيمها الافتراضية؛ رفض المراجع غير المثبتة بـ SHA256 في مشغلات الحزمة |
| مسارات تشغيل بديلة تولد إعدادات بطريقة مختلفة | مرتفع: تفاوت جودة المفاتيح أو مشاركة مفتاح النسخ الاحتياطي مع التشفير | استخدام المولد الآمن المشترك في PowerShell وBash مع الحفاظ على أي `.env` موجود |

### حماية المستندات

يتحقق المسار من UUID وملكية سجل `patient_portal_documents` وظهوره للمريض. يقبل مراجع التخزين المدارة `/api/documents/<UUID>/download` و`/uploads/documents/<filename>`؛ العناوين المطلقة تتطلب تطابق أصل الواجهة أو البوابة المعرّف في الإعدادات.

يشترط سجل `documents` ملكية المريض نفسه وعدم الحذف. يُفحص اسم الملف ومساره الحقيقي لمنع الخروج من مجلد التخزين. لا ينفذ الخادم طلب HTTP إلى المرجع المخزن. يُرسل الملف كمرفق مع `no-store` و`nosniff` وسياسة محتوى مقيدة، ولا تُعيد قائمة المستندات رابط التخزين الداخلي.

**المراجع الخارجية والقديمة غير المدعومة تحتاج ترحيلاً منظماً**؛ تعود بخطأ 503 بدلاً من السماح بتنزيل غير متحقق منه. لا يُفترض توافق البيانات القديمة تلقائياً.

### الفواتير وPDF

المسار `/api/portal/invoices/:invoiceId/pdf` لا يتطلب منح المريض صلاحيات مالية للموظفين. يفحص الملكية والحالة والروابط قبل التوليد، ويحسب الرصيد من المدفوعات المكتملة والاستردادات المعالجة والإشعارات الدائنة غير المعكوسة، ويسجل التنزيل في تدقيق البوابة.

التوليد يستخدم PDFKit دون متصفح أو تحميل خطوط من الإنترنت. خطا Noto Sans وNoto Sans Arabic مرفقان مع الترخيص والمصدر والبصمات في `backend/assets/fonts/README.md`. جرى إصلاح تشكيل الكلمات العربية وفحص فاتورة مصورة واختبار فاتورة متعددة الصفحات. المخرجات تتضمن البيانات المالية الأساسية؛ أي شكل ضريبي إلزامي محلياً يحتاج اعتماداً مستقلاً.

أضيف `format=pdf` لدوال تنزيل تقارير المريض والطبيب. معاينة HTML المقصودة باقية، ولم يتغير السلوك الافتراضي لمسار التقارير.

## أدلة التحقق

| التحقق | النتيجة | حدود الدليل |
|---|---|---|
| اختبارات الخادم كاملة | 156 مجموعة، 1259 اختباراً ناجحاً، دون اختبارات معلقة | تشمل محاكاة واعتماديات اختبار؛ ليست قبولاً لجميع وظائف المؤسسة |
| إعادة اختبارات المناطق المتأثرة بعد التعديلات الأخيرة | 5 مجموعات، 44 اختباراً ناجحاً | الجلسات وإعادة استخدام الرموز وملكية التنزيل وPDF وسلامة الحزمة |
| PostgreSQL 18 مؤقتة + Express + HTTP وملفات جلسة عميل | 28 حالة تحقق ناجحة | بيانات مصطنعة ومخطط مصغر؛ ليس ترحيلاً لمخطط الإنتاج بالكامل |
| اختبارات واجهة البوابة | 6 ملفات، 26 اختباراً ناجحاً | تشمل منع إرسال اعتماديات المستند إلى أصل خارجي |
| فحص الأنواع والتدقيق وبناء البوابة | ناجح | لا يغني عن قبول المستخدم في بيئة النشر |
| Nginx فعلي وTLS وmTLS وعزل المسارات | 269 حالة تحقق ناجحة | مدخل محلي وخادم خلفي مصطنع، وليس صور Docker الإنتاجية |
| Compose وتهيئة المفاتيح | 55 حالة تحقق ناجحة | دون تشغيل Docker؛ مراجع صور مصطنعة للتحقق من الاستيفاء فقط |
| صياغة مشغلات PowerShell وBash المعدلة | ناجحة | لا تعني تشغيل الحاويات أو نجاح جاهزيتها |

اختبار PostgreSQL أثبت وصول ملف الجلسة تلقائياً إلى التجديد، ودوران الرمز مع إبقاء معرف الجلسة، ورفض JWT بعد خروج دون Bearer، وإلغاء عائلة الرموز، وعدم إلغاء دخول أحدث بخروج جلسة قديمة. وأثبت رفض نوع حساب خاطئ دون إلغاء رموزه، ومنع دخول طبيب موقوف، ورفض فواتير أجنبية أو ملغاة أو متعارضة الروابط ومستندات لا تتطابق ملكيتها بين سجلي البوابة والتخزين.

أوامر إعادة التحقق من جذر المستودع:

```powershell
node scripts/generate-portal-api-policy.cjs --check
node scripts/verify-production-access-config.cjs
node scripts/verify-portal-ownership-postgres.cjs
node scripts/verify-remote-access-local.cjs <nginx-executable> <openssl-executable>
```

يشترط اختبار PostgreSQL أدواتها المحلية؛ يمكن تحديد مجلدها عبر `VIARA_TEST_PG_BIN`. ينشئ عنقوداً جديداً داخل `scratch/remote-access-validation` بمنفذ محلي متاح ويوقفه في النهاية. لا يقرأ `.env` ولا يتصل بعنقود قائم. توجد نتائج الاختبار وآثار PDF المصطنعة في المجلد نفسه. مصادقة `trust` المحلية في هذا العنقود للاختبار المصطنع فقط.

## متطلبات النشر والمخاطر المتبقية

1. توفير صور الحاويات المراجعة ومراجع `image@sha256` الصحيحة لجميع متغيرات الصور، ومنها Caddy وWireGuard، وضبط أصول HTTPS والشبكات. **لم تُختلق بصمات إصدار ولم تُصدر صور إنتاج هنا.** فراغ قيم الصور في القالب مقصود لمنع اختيار إصدار تلقائي غير معتمد.
2. إعادة بناء صور الخادم والبوابة لتضمين الشيفرة والخطوط وسياسة Nginx المحدثة، واختبار الحزمة كاملة على Docker Engine Linux؛ محرك Docker غير متاح في هذه الجلسة.
3. جرد روابط المستندات القديمة وربطها بملفات مدارة صحيحة بعد التحقق من الملكية والفحص الأمني. لا تُجلب ملفات خارجية آلياً من URL غير موثوق. مراجعة الفواتير ذات روابط المرضى المتعارضة دون تعديل مالي آلي.
4. توقع الحاجة لدخول جديد مرة واحدة عند الانتقال من مسار ملف الجلسة القديم. المحافظة على المفاتيح و`.env` الحاليين؛ تحديث مراجع الصور والأصول حسب خطة الإصدار.
5. إكمال MFA وهوية الوصول السريري وإدارة شهادات الأجهزة وسياسة مشاركة النتائج، واختبار الصلاحيات عبر المدخل العام الفعلي. هذه المرحلة لم تضف مزود هوية أو MFA جديداً.
6. إجراء اختبار استعادة نسخة احتياطية واختبارات الحمل ونقل دراسات DICOM وعرضها وكتابة التقارير على الشبكة المستهدفة. لا توجد بيئة تجريبية مخصصة أو أرقام تزامن مؤكدة؛ لا توجد شهادة أداء أو تقدير سعة نهائي.

القرار: الإصلاحات المذكورة قابلة للمراجعة واجتازت الاختبارات المحددة. جاهزية الإطلاق الكامل مشروطة بالتحقق التشغيلي والسريري أعلاه، ولا يمثل نجاح الاختبارات المحلية موافقة على التشغيل ببيانات مرضى حقيقية.
