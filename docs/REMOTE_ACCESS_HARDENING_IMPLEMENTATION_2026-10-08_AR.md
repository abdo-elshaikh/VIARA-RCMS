# تنفيذ تقوية الوصول البعيد — VIARA

> Update 2026-10-08: phase 2 supersedes the image-tag limitation and raises configuration checks to 55. See [application hardening and current deployment requirements](REMOTE_ACCESS_APPLICATION_HARDENING_2026-10-08_AR.md).

**التاريخ:** 8 أكتوبر 2026. **النطاق:** تطبيق ضوابط محلية في المصدر وقوالب النشر، والتحقق منها ببيانات اصطناعية. لم تُنشر الخدمات على الإنترنت ولم تتغير بيئة `.env` الحالية أو قواعد البيانات أو مفاتيح التشفير المثبتة.

## الملخص التنفيذي

تم تحويل جزء الأمان الأول من المقترح المعماري إلى تغييرات تنفيذية: سياسة سماح دقيقة لواجهات البوابة العامة، إغلاق الربط الشبكي الافتراضي للخدمات الداخلية، فصل Caddy العام عن واجهة الموظفين، أسرار إلزامية وتوليد تشفيري متوافق، وضبط أدوات التحقق كي لا تعتبر تعذر الاتصال وحده دليلاً على الحماية.

اجتاز Nginx فعلي 261 فحص تكامل محلي، واجتازت إعدادات Compose ومولدات الأسرار 45 فحصاً مستقلاً، واجتازت البوابة 26 اختباراً. هذه النتائج تتحقق من التغييرات ضمن نطاقها، ولا تمثل اختباراً لصلاحيات بيانات الإنتاج أو جاهزية تشخيص طبي عن بعد.

## ما تغير

### 1. عزل API البوابة

- المصدر المركزي: `portal/nginx/portal-api-policy.json`، مع توليد نسختين متطابقتين بواسطة `scripts/generate-portal-api-policy.cjs`.
- السياسة تربط **الطريقة والمسار**، وتمنع المسارات غير المعروفة افتراضياً. تشمل الدخول الخاص بالمريض والطبيب المحول، وتجديد جلسة البوابة، والبيانات والإشعارات والرسائل والطلبات، ومسارات تنزيل PDF المستخدمة حالياً، وواجهات الصفحة العامة.
- تمنع دخول الموظفين وواجهات الإدارة وقوائم مراجعة الطلبات للموظفين وPACS وwebhook والتصدير الداخلي وإدارة المفاتيح الشخصية.
- تطبيقها داخل صورة البوابة وعند المدخل العام يمنع تجاوز سياسة الحافة بالوصول إلى خدمة البوابة نفسها. تظل صلاحيات التطبيق والتحقق من ملكية المورد إلزامية.
- فحص CI يمنع اختلاف الملفات المولدة عن المصدر. أي وظيفة بوابة جديدة تحتاج مراجعة وتحديثاً للسياسة وبناء الصورة وتحديث الحافة.
- لا تُسجل query strings أو Authorization أو referrers في صيغة سجل البوابة الجديدة؛ تُحجب توكنات مسار روابط التقارير القديمة من السجل أيضاً.

هذه طبقة تقييد للمسارات وليست إنشاء خدمة BFF مستقلة أو إعادة تصميم للصلاحيات داخل الخادم. تشمل قائمة السماح بعض مسارات الخادم المشتركة التي تستخدمها البوابة؛ صلاحياتها وسلوكها الحقيقي يحتاجان اختباراً على بيئة تطبيق كاملة.

### 2. إعدادات الشبكة والنشر

- أصبحت واجهتا الموظفين والبوابة ومنفذ DICOM مرتبطة بـ loopback افتراضياً في حزمة الإنتاج؛ منافذ API وقاعدة البيانات وREST وOHIF كانت محلية وتبقى كذلك.
- قالب المدخل السريري يستمع على عنوان WireGuard الخاص النموذجي `10.20.0.1` بدلاً من جميع الواجهات، ويستمر في فرض mTLS.
- ملف Caddy العام يوجه إلى البوابة فقط، وأزيلت منه مسارات الموظفين وPACS والإدارة. فحص جاهزيته يستخدم واجهته الإدارية المحلية دون نشرها.
- ضبط عناوين الوكلاء الموثوقين المحددة لتشمل Caddy وواجهتي الموظفين والبوابة؛ لا توسيع الثقة إلى شبكة كاملة.

**أثر الانتقال:** يحتاج مسؤول الموقع إلى عنوان واجهة أجهزة التصوير الفعلي وقواعد جدار ناري للأجهزة قبل اختبار C-STORE/MWL. قيم الربط الصريحة في `.env` موجودة سابقاً تتغلب على الافتراضيات؛ لم نغيرها تلقائياً. مستخدمو Caddy السابقون للوصول إلى الموظفين يحتاجون الانتقال إلى المدخل السريري الخاص.

### 3. الأسرار والتشغيل الأول

- تسعة أسرار لم تعد تقبل قيم fallback مشتركة: كلمات مرور PostgreSQL وRedis وOrthanc، ومفاتيح JWT وتشفير البيانات والنسخ الاحتياطي وblind index، وتوكن المقاييس وسر webhook.
- Compose يرفض القيم المفقودة والفارغة. هذا يمنع fallback ولا يغني عن تقييم قوة القيم الموجودة أو مراجعة من يستطيع قراءتها.
- `scripts/initialize-env.ps1` يستخدم RandomNumberGenerator ومتوافق مع PowerShell 5.1، ويولد مفاتيح مستقلة بطول 32 بايت دون طباعة قيمها. ملف UTF-8 دون BOM، ولا يستبدل ملفاً موجوداً.
- `scripts/initialize-env.sh` يستخدم OpenSSL دون بديل يعتمد على الوقت، وبصلاحيات ملف خاصة وإنشاء مكتمل قبل النشر؛ يتوقف عند فشل التوليد. يستخدم مشغّل Linux هذا السكربت، ويستخدم مشغّل Windows نظيره PowerShell.
- لم تتغير أي مفاتيح قائمة. لا يجوز تدوير مفتاح البيانات أو النسخ الاحتياطي على تثبيت قائم دون خطة ترحيل واستعادة.

### 4. عميل البوابة وأدوات التحقق

- أصبح عنوان API الافتراضي `/api` من نفس أصل البوابة، بدلاً من localhost على جهاز الزائر.
- إصلاح حل الروابط النسبية لتنزيل المستندات، ومنع إرسال bearer token إلى أصل مختلف عبر URL مستند يرجعه الخادم.
- أدوات قبول الوصول البعيد لا تستخدم `-k`، وتحتاج نجاح اتصال بشهادة عميل صالحة لإكمال التحقق السريري. تدعم تعيين CA داخلية للمدخل السريري.
- فشل TLS 1.0 من العميل يوصف بأنه عدم تفاوض من هذا العميل، وليس شهادة قاطعة بأن سياسة الخادم سليمة؛ يلزم فحص إعداد الخادم أيضاً.
- استخدام PEM/PFX أو شهادة من مخزن Windows يعتمد على TLS backend الخاص بنسخة curl. يجب تهيئة ذلك على جهاز القبول؛ لم تُستورد شهادات تجريبية إلى مخزن النظام.

| Nginx 1.30.5 محلي: syntax وتشغيل HTTP/HTTPS والتحقق من شهادة الخادم وmTLS | 261 فحصاً ناجحاً | upstream اصطناعي؛ لا اختبار لقواعد ملكية بيانات حقيقية |
| مرور وظائف البوابة ورفض مسارات الموظفين والطرق غير المسموحة | ناجح في البوابة والحافة | الرفض تحقق قبل وصول الطلب إلى upstream؛ السماح لا يثبت نجاح controller الفعلي |
| منع تسرب توكن رابط التقرير وquery في سجلات Nginx | ناجح | صيغة سجلات Nginx المعدلة فقط؛ يلزم فحص سجلات بقية الخدمات في النشر الفعلي |
| مولدا الأسرار PowerShell 5.1 وBash وحفظ ملف قائم وعدم طباعة المفاتيح | ناجح | بيانات اصطناعية داخل scratch |
| Compose بملف بيئة اصطناعي وربط محلي ورفض كل سر فارغ | 45 فحصاً ناجحاً إجمالاً مع اختبارات التوليد | تحقق إعداد دون Docker Engine ودون بدء حاويات |
| اختبارات البوابة | 6 ملفات / 26 اختباراً ناجحاً | منها 4 اختبارات لتنزيل المستندات ومنع تسريب التوكن إلى أصل خارجي |
| TypeScript وESLint وبناء Vite للإنتاج | ناجح | بناء البوابة فقط؛ لا ادعاء بإعادة اختبار النظام كله |
| تنسيق الملفات المعدلة وsyntax لسكربتات Bash/PowerShell | ناجح | أدوات curl الخارجية تحتاج اختباراً على جهاز الهدف |

يتوفر الاختبار القابل للإعادة في `scripts/verify-remote-access-local.cjs` و`scripts/verify-production-access-config.cjs`. تستخدم أدوات الاختبار مجلدات scratch ومستمعات localhost مؤقتة، وتوقف عمليات Nginx الخاصة بها. شهادات الاختبار قصيرة العمر وغير موثوقة في مخزن النظام.

## ما يلزم قبل النشر الفعلي

1. إعادة بناء صورة البوابة وتوزيعها؛ تعديل مصدر Nginx لا يغير صورة حاوية قديمة. تثبيت صور الإصدار المعتمدة بالـ digest وفحصها؛ هذه المرحلة لم تحسم قائمة digests لكل خدمات المنتج.
2. تحديد النطاقات والشهادات وواجهة VPN وواجهة أجهزة التصوير، ومراجعة قيم `.env` الحالية والجدار الناري وNAT ومسار الثقة الفعلي.
3. تشغيل اختبار القبول من شبكة خارجية وجهاز سريري معتمد، مع التحقق من عدم وجود مسار مباشر يتجاوز الحافة. Docker Engine غير متاح في جلسة التنفيذ الحالية، لذلك لم يُختبر تشغيل حزمة الحاويات الكاملة أو Caddy فعلياً.
4. اختبار تسجيل الدخول والتجديد والخروج وملكية بيانات المرضى والإحالات وتنزيل التقارير والمستندات والفواتير على تطبيق كامل. معالجة فجوات controller أو الصلاحيات التي تظهر؛ اختبار Nginx لا يعوض هذا الاختبار.
5. استكمال أعمال مطابقة الصور والفحوصات، وتعارض التأليف واعتماد التقارير، وقياس DICOM والذاكرة والرفع والتزامن، وتجربة الاستعادة والقبول السريري كما في التقرير المعماري.

**التقييم:** ضوابط الوصول الافتراضية أصبحت أكثر أماناً ومسنودة باختبارات محلية. لم يصدر اعتماد GO للنشر العام أو للتشخيص البعيد؛ يتطلب ذلك إغلاق أعمال الموقع والاختبارات المتبقية أعلاه.
