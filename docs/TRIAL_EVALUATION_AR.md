# دليل تشغيل تجربة VIARA التقييمية

هذه آلية لفريق VIARA لإنشاء بيئة تقييم معزولة قصيرة المدة لكل عميل. **ليست حزمة تثبيت ذاتي للعميل، وليست إصداراً إنتاجياً أو اعتماداً سريرياً.** لا تستخدمها مع بيانات مرضى حقيقية، ولا تعرضها للإنترنت دون مراجعة أمنية وإعداد حافة وصول معتمد.

## المتطلبات

- مضيف Linux أو Linux VM على Windows Server مع Docker Engine وDocker Compose v2.
- نسخة المستودع ومكوناته التابعة، واتصال بسجلات الصور المطلوبة لبناء/سحب الخدمات.
- ملف `.env` محلي غير متعقب يحتوي إعدادات التطوير وأسراراً صالحة. لا تنسخ أسرار بيئة الإنتاج إليه.
- مفتاح توقيع الترخيص الخاص محفوظاً وفق ضوابط فريق الإصدار، ومفتاحه العام الذي يتحقق به التطبيق. يجب أن يطابق المفتاح العام المضمّن في التطبيق المفتاح الخاص، أو أن يُمرر المفتاح العام المطابق عبر `LICENSE_PUBLIC_KEY`. لا تنشئ زوج مفاتيح جديداً لهذا الغرض إلا إذا كان التطبيق سيستخدم مفتاحه العام المطابق.
- موافقة على معرف العميل ومدة التجربة؛ الأداة تصدر ترخيص `trial` موقّعاً وتبدأ خدمات وتخزن بيانات العرض.

تحقق من Docker دون تشغيل أي خدمات:

```sh
docker compose version
docker info --format '{{.OSType}}'
```

يجب أن تكون نتيجة نوع المحرك `linux`. جهّز `.env` من القالب الجذري وفق إجراءات التطوير المحلية، واملأ القيم اللازمة للتشغيل المحلي مثل عناوين `localhost` وكلمات المرور المطلوبة. يجب أن يكون المفتاح العام الذي يتحقق به التطبيق (المضمّن أو قيمة `LICENSE_PUBLIC_KEY`) متوافقاً مع مفتاح التوقيع الخاص لدى فريق الإصدار. لا تطبع أو ترسل قيم الأسرار في التذاكر أو المحادثات.

## إنشاء تجربة

من جذر المستودع، استخدم معرفاً تقنياً لاتينياً للترخيص والمشروع، ويمكن تمرير اسم العرض بالعربية بشكل منفصل:

```sh
node scripts/demo-provision.js provision --customer TaibaRadiology --display-name "طيبة للاشعة" --days 14 --max-users 3
```

معرف العميل يجب أن يتوافق مع قيود الترخيص (أحرف/أرقام لاتينية وشرطة وشرطة سفلية ونقطة)؛ اسم العرض يُحفظ في سجل التجربة دون استخدامه كمعرف ترخيص أو اسم مشروع Docker. استخدم `TaibaRadiology` في أوامر `demo:reclaim` لمطابقة المعرف. المدة الافتراضية 14 يوماً والحد الافتراضي ثلاثة مستخدمين. عند نجاح العملية، تقوم الأداة بـ:

1. تسجيل مدة التجربة في سجل محلي.
2. إصدار ترخيص تقييم موقّع بالمدة نفسها.
3. توليد أسرار مستقلة للتجربة وعدم نسخ أسرار المكدس الرئيسي إليها.
4. إنشاء مشروع Compose منفصل وقاعدة PostgreSQL وتخزين Orthanc وملفات Worklist مستقلة، مع انتظار جاهزية قاعدة البيانات قبل الترحيلات.
5. تشغيل الخدمات وتحميل بيانات العرض الاصطناعية.

قد يستغرق بدء ClamAV والخدمات وقتاً. إذا فشل التشغيل، تتحول التجربة إلى حالة طلب إزالة؛ راجع الخطأ وسجل `node scripts/demo-provision.js list` قبل إعادة المحاولة. لا تحذف المجلدات أو وحدات Docker يدوياً.

تعرض الأداة أسماء الحسابات التجريبية، لكنها لا تطبع كلمة مرور المستخدمين إلى مخرجات provision. كلمة مرور حسابات التطبيق محفوظة في متغير `TEST_USER_PASSWORD` في ملف الإعداد الخاص بهذه التجربة تحت `scratch/demos/`. استخرجها فقط على المضيف المصرح، ثم أرسلها للمقيّمين بقناة آمنة، ودوّرها/أزلها عند انتهاء العرض. بيانات دخول حسابات البوابة التجريبية الثابتة للاختبارات البرمجية لا يجوز استخدامها إذا أتيح الوصول من جهاز آخر.

## الوصول إلى واجهات التجربة

المنافذ الافتراضية مرتبطة بـ`127.0.0.1` على المضيف:

| الواجهة | العنوان المحلي الافتراضي |
|---|---|
| تطبيق الموظفين | `http://localhost:55173` |
| بوابة المرضى والأطباء | `http://localhost:55174` |
| عارض OHIF | `http://localhost:53005` |
| Orthanc REST | `http://localhost:58042` |

هذه الروابط محلية على الخادم؛ لا تعني أن التجربة متاحة عن بُعد. لا تغيّر الربط إلى `0.0.0.0` ولا تفتح المنافذ مباشرة. إذا لزم وصول تجريبي عن بُعد، استخدم VPN أو حافة وصول محمية ومعتمدة بعد مراجعة إعداد TLS والمصادقة والجدار الناري. لا تكشف قاعدة البيانات أو Orthanc أو DICOM للإنترنت.

## متابعة التجارب وإنهاؤها

```sh
node scripts/demo-provision.js list
node scripts/demo-provision.js reclaim --customer TaibaRadiology
```

الإزالة تحذف حاويات التجربة ووحداتها بما فيها قاعدة البيانات وملفات الصور، وتحذف ملف أسرار التجربة المحلي؛ ستطلب الأداة تأكيد اسم المشروع. نفّذها بعد انتهاء الفترة أو بطلب صاحب التجربة. لمعاينة التجارب المنتهية دون حذف:

```sh
node scripts/demo-provision.js reap --dry-run
```

لا تحذف جميع التجارب تلقائياً. أمر `reap --yes` هدّام ويزيل بيانات كل التجارب المنتهية التي تديرها الأداة؛ استخدمه فقط ضمن إجراء تشغيلي معتمد وبعد مراجعة المعاينة.

## حدود التجربة

- البيانات المحملة بيانات اصطناعية؛ لا تستورد بيانات سريرية أو صور مرضى حقيقية.
- الترخيص مؤقت ومحدود، ولا يمنح صلاحية الاستخدام التشغيلي أو التشخيصي.
- المكدس منفصل لكل تجربة على مستوى قاعدة البيانات وتخزين Orthanc؛ لا تشارك قواعد بيانات بين العملاء.
- الاختبارات الآلية ونجاح تشغيل Docker لا يثبتان سلامة سريرية أو امتثالاً تنظيمياً أو جاهزية إنتاجية.
- عند الحاجة إلى تشغيل لدى العميل، انتقل إلى مسار إصدار العميل المعتمد، ومتطلباته للصور المثبتة والوثائق والترخيص والإعدادات الأمنية الخاصة بالموقع.
