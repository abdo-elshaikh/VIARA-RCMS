# مراجعة منظومة الألوان — الوضعان الفاتح والداكن

**التاريخ:** 5 أكتوبر 2026  
**النطاق:** واجهة الإدارة في `frontend/`، بما في ذلك رموز الألوان، تبديل الوضع، تخصيص لوحة الألوان، قواعد CSS المشتركة، وحالات التباين العالي.

## الخلاصة التنفيذية

تملك الواجهة أساسًا منظمًا نسبيًا: رموزًا دلالية للأسطح والنصوص والحالات، اختيار الوضع الفاتح/الداكن/تلقائيًا، وتوليدًا للون الأساسي مع فحص تباين للنص فوق اللون الأساسي. كشف التدقيق أربع فجوات مرتبطة بالتخصيص والتباين العالي واتساق الوضع الداكن، وعولجت ضمن التعديلات الموضحة أدناه.

كانت اللوحة الافتراضية تجتاز الاختبارات، لكن التباين لم يكن مضمونًا بعد تخصيص النصوص والأسطح. كذلك لم تكن كل العناصر النائبة تتبع خيار التباين العالي، واستخدمت ترويسة الصفحة الداكنة ألوانًا ثابتة لا تتبع اللوحة، مع اختلاف قيمة حد قوية بين CSS وJavaScript.

هذه مراجعة ساكنة للشيفرة واختبارات الوحدة؛ لم تُنفذ مقارنة بصرية آلية لكل صفحة ومكوّن في المتصفحات أو جولة تدقيق WCAG كاملة.

## ما يعمل جيدًا

- تهيئة الوضع المحفوظ أو تفضيل النظام قبل العرض تقلل وميض الانتقال بين الفاتح والداكن.
- الوضعان الافتراضيان يختبران تباين النص الأساسي (7:1) والثانوي والخافت (4.5:1) مع السطح في [themePalette.test.js](../frontend/src/utils/__tests__/themePalette.test.js#L36).
- اللون الأساسي المخصص يُختار له لون نص مقابل قابل للقراءة، وتُشتق ألوان الحالات من اللوحة.
- رموز `canvas` و`surface` و`text` و`border` مستخدمة على نطاق جيد في عناصر التصميم المشتركة.

## نتائج التحقق والحدود

- `npm test --prefix frontend -- --run src/utils/__tests__/themePalette.test.js` — نجح: 28 اختبارًا، وتشمل الآن تخصيصات متعارضة في الوضعين، وحالة يستحيل فيها بلوغ الحد لجميع الأسطح، ومزامنة قيمة CSS الداكنة، وتحققًا من رموز الترويسة وplaceholder والتباين العالي.
- ESLint للملفات المعدلة — نجح.
- `npm run build --prefix frontend` — تعذر في الفحص الأخير بسبب استيراد `TriangleAlert` غير المصدّر من `lucide-react` في [ToastHub.jsx](../frontend/src/components/ui/ToastHub.jsx)، وهو ملف غير متعلق بإصلاح الألوان ولم يُعدّل ضمنه. أظهر البناء السابق أيضًا تحذير تقسيم دائري بين `framework` و`vendor`.
- فحص ESLint على المشروع كاملًا ما زال يتوقف عند توجيه تعطيل غير مستخدم في [usePageTitle.js](../frontend/src/hooks/usePageTitle.js)، إلى جانب تحذيرين في ملفات أخرى خارج نطاق إصلاح الألوان.
- لم يُجر فحص تباين آلي شامل لكل تركيبة لون في الشاشات، أو تدقيق WCAG 2.2 AA لكل المكونات والحالات التفاعلية.
- لا يغني هذا عن معاينة الواجهات في الوضعين على شاشات فعلية، أو تدقيق WCAG 2.2 AA للنصوص والعناصر التفاعلية والرسوم البيانية.

## الإصلاحات المنفذة

1. **COL-01:** يختار التطبيق أقرب لون نص يحقق تباين 7:1 للنص الأساسي و4.5:1 للنص الثانوي والخافت عبر خلفيات اللوحة الأربع. يعرض محرر الألوان رسالة عند تعديل النص تلقائيًا، وتحذيرًا واضحًا إذا كانت ألوان الأسطح متباعدة لدرجة تمنع لونًا واحدًا من تحقيق النسبة المطلوبة؛ عندها يُستخدم أفضل تباين ممكن.
2. **COL-02:** أصبح placeholder يعتمد الرمز الدلالي نفسه، ويضبط وضع التباين العالي ألوان النص والخلفيات والحقول بوضوح في الوضعين، مع إبراز placeholder بنسبة تباين أعلى.
3. **COL-03:** أصبح تدرج ترويسة الوضع الداكن مشتقًا من رموز السطح والخلفية القابلة للتخصيص بدل الألوان الكحلية الثابتة.
4. **COL-04:** تطابقت قيمة `--border-strong` الداكنة في CSS مع قيمة لوحة التشغيل، وأضيف اختبار يمنع رجوع الاختلاف.

تبقى حالة الأسطح المتعارضة مستحيلة رياضيًا مع رمز نص واحد؛ لذلك لا يُدّعى ضمان النسبة المطلوبة لهذه الحالة، بل يظهر تحذير وتُختار الدرجة ذات أفضل تباين ممكن. يظل التدقيق البصري الشامل لكل الصفحات والمتصفحات خارج نطاق اختبارات الوحدة والبناء الحالية.
